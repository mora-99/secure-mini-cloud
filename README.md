# Secure Mini Cloud

A self-hosted, AWS-style mini cloud built **secure-by-design**: identity, least privilege, audit logging, attack detection and compliance mapping from day one.

Built as a hands-on cloud security lab while studying for Microsoft SC-500 and AWS certifications.

## Architecture (current)

~~~
Client (AWS CLI)
      │  S3 API (127.0.0.1:3900)
      ▼
┌───────────────────────┐
│  Garage (S3 storage)  │  ← per-key, per-bucket permissions
└───────────────────────┘
~~~

Planned layers: identity provider (Keycloak), secrets management (OpenBao), TLS gateway (Caddy), policy-as-code (OPA), audit logging + SIEM (Loki/Grafana), ML anomaly detection.

## Security decisions (Phase 1)

- **No network exposure:** API ports published to `127.0.0.1` only; the internal RPC port is not published.
- **No secrets in Git:** `rpc_secret` and admin tokens are generated by `scripts/gen-garage-config.sh` into a git-ignored file.
- **Least privilege:** separate read-write (`app-rw`) and read-only (`auditor-ro`) keys; neither can create buckets.
- **Hardened container:** read-only config mount and a memory limit.
- **Credential hygiene:** keys stored in `chmod 600` files and loaded into the AWS CLI without displaying secrets; exposed keys were rotated.

## Verified: least privilege works

~~~
$ aws --profile mc-ro s3 cp test.txt s3://demo-bucket/hack.txt

PutObject operation: Forbidden: Operation is not allowed for this key.
~~~

~~~

## Mora Cloud Console (Phases 3–7)

A self-hosted cloud portal, like a mini AWS Console / Azure Portal, built on top of the storage and identity layers.

| Phase | Feature | Security highlight |
|---|---|---|
| 3 | Console login via Keycloak (OIDC) | Authorization Code + PKCE, MFA (TOTP), signed session cookie |
| 4 | Storage browser (buckets, upload, download, delete) | RBAC enforced in the app **and** by Garage per-key permissions |
| 5 | Audit log | Every action and denial logged; SHA-256 hash chain makes edits detectable |
| 6 | Attack & detect | Brute force, privilege probing, log tampering, stored XSS tested — see `docs/attack-and-detect.md` |
| 7 | GRC report | Controls mapped to ISO 27001:2022 and CIS v8 + risk register — see `docs/grc-report.md` |

### Roles (least privilege)

| Permission | admin | developer | auditor |
|---|:-:|:-:|:-:|
| List / view / download | ✅ | ✅ | ✅ |
| Upload | ✅ | ✅ | ❌ |
| Delete | ✅ | ❌ | ❌ |
| Read audit log | ✅ | ❌ | ✅ |

Users with write permission get the read-write Garage key; everyone else gets the read-only key,
so even an application bug could not let an auditor write data (defense in depth).

### Run the console
```bash
cd console && . .venv/bin/activate
uvicorn app:app --host 127.0.0.1 --port 8000
```
Secrets live in `console/.env` (gitignored, mode 600): Keycloak client secret, session secret, Garage keys.
